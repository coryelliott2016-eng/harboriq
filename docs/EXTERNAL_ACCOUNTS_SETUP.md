# External Accounts Setup (AWS, Twilio, Cloudflare)

HarborIQ's code already expects credentials for three external services —
AWS (off-host backups), Twilio (SMS), and Cloudflare (CDN/WAF) — but none of
these accounts exist yet. This guide is the one place to go from "no
account" to "credential in `.env`" for each of them.

**What this guide is not:** none of the steps below that require creating an
account, verifying an identity, or attaching a payment method can be
scripted. AWS, Twilio, and Cloudflare all require a human to sign up in a
browser, verify an email/phone number, and (for AWS and Twilio) enter a
credit card — that is deliberate fraud/abuse prevention on their end, and no
API exists to bypass it. **Cory has to do the account-creation steps
himself.** Everything *after* the account exists and an API key/token has
been generated — bucket creation, IAM policy, phone number purchase, WAF
configuration — is handled by the provisioning scripts in `scripts/`.

| Service    | Why HarborIQ needs it                                             | Provisioning script                   |
| ---------- | ------------------------------------------------------------------ | -------------------------------------- |
| AWS        | Off-host S3 backup target for `scripts/backup_db_s3.sh` (Phase 16) | `scripts/provision_aws_backup.py`      |
| Twilio     | Outbound SMS transport (`app/services/sms.py`, Phase 11)           | `scripts/provision_twilio_number.py`   |
| Cloudflare | CDN caching + WAF in front of the reverse proxy (Phase 16)         | `scripts/provision_cloudflare.py`      |

---

## 1. AWS (off-host database backups)

**Why HarborIQ needs it:** `scripts/backup_db_s3.sh` pushes the nightly
`pg_dump` off-host once `BACKUP_S3_BUCKET` is set — without an AWS account,
backups only ever live on the same disk as the database itself, one bad
disk away from losing both the DB and its backups.

### Sign up (manual, in a browser)

1. Go to **<https://aws.amazon.com/>** and click "Create an AWS Account."
2. You'll need: an email address, a phone number (for SMS/voice
   verification), and a credit or debit card. AWS charges a small
   temporary authorization to verify the card — it is refunded, not a real
   charge.
3. Choose the **Basic support plan** (free) unless there's a specific
   reason to pay for Developer/Business support.
4. Once the account exists, sign in to the **AWS Console** and go to
   **IAM → Users** (or **IAM Identity Center**, if preferred) to confirm
   you're not just using the root account for everyday access — AWS's own
   best practice is to never use root credentials for anything beyond
   initial setup and billing. The provisioning script below creates a
   dedicated, least-privilege IAM user for the backup script itself, so
   root credentials are never put in `.env`.
5. Nothing else needs to be created by hand — no bucket, no IAM policy, no
   access key. `scripts/provision_aws_backup.py` does all of that.

### Cost

S3 Standard storage is billed per GB-month, tiered: **$0.023/GB for the
first 50 TB/month** (US East region), plus small per-request charges (PUT
~$0.005/1,000 requests, GET ~$0.0004/1,000 requests) — see
[AWS's official S3 pricing page](https://aws.amazon.com/s3/pricing/). For
HarborIQ's use case (one gzipped `pg_dump` per day, likely low
tens-of-MB to a few GB per dump), realistic storage cost is well under
$1/month before AWS's free tier (5 GB free for the first 12 months) is even
exhausted. **Verify current pricing on the link above before signing up** —
AWS pricing pages are the source of truth and can change.

### Generate the credential

The credential here is an **IAM access key ID + secret access key**, and
it's generated by the provisioning script below, not by hand in the
console — that keeps the key scoped to exactly the least-privilege policy
the script creates, rather than an operator accidentally attaching
`AdministratorAccess`.

### Run the provisioning script

Once the AWS account exists, generate a **temporary** IAM access key for an
admin/power-user identity (Console → IAM → Users → your user → Security
credentials → "Create access key") just to run this script — or run it from
[AWS CloudShell](https://aws.amazon.com/cloudshell/) in the console, which
is already authenticated as you and needs no key at all. That temporary key
only needs to exist long enough to run the script once; it is not what ends
up in HarborIQ's `.env`.

```bash
pip install boto3   # one-time, ops-only — see the script's docstring
export AWS_ACCESS_KEY_ID=<your-temporary-admin-key>
export AWS_SECRET_ACCESS_KEY=<your-temporary-admin-secret>
export AWS_DEFAULT_REGION=us-east-1

python scripts/provision_aws_backup.py \
  --bucket my-company-harboriq-backups \
  --region us-east-1
```

The script prints a **new, separate** access key ID/secret for a
newly-created `harboriq-backup` IAM user, scoped to only that one bucket.
**That is the credential that goes in `.env`** — not the temporary
admin/CloudShell key used to run the script.

### Env vars to fill in afterward

```
AWS_ACCESS_KEY_ID=<from the script's output>
AWS_SECRET_ACCESS_KEY=<from the script's output — shown ONCE, save immediately>
AWS_DEFAULT_REGION=us-east-1
BACKUP_S3_BUCKET=my-company-harboriq-backups
BACKUP_S3_PREFIX=harboriq-backups
```

These are read directly by the AWS CLI (`AWS_ACCESS_KEY_ID` /
`AWS_SECRET_ACCESS_KEY` / `AWS_DEFAULT_REGION`) inside
`scripts/backup_db_s3.sh`, and `BACKUP_S3_BUCKET`/`BACKUP_S3_PREFIX` match
`app/core/config.py`'s `backup_s3_bucket`/`backup_s3_prefix` settings
(documentation-only there — the shell script reads the env vars directly,
see `scripts/backup_db_s3.sh`'s own header comment).

## 2. Twilio (outbound SMS)

**Why HarborIQ needs it:** `app/services/sms.py` sends real SMS (job
reminders, dispatch notifications) once `twilio_account_sid` /
`twilio_auth_token` / `twilio_from_number` are set — until then, it
console-logs messages instead of sending them (fine for dev, not for
production use with real customers).

### Sign up (manual, in a browser)

1. Go to **<https://www.twilio.com/try-twilio>** and create an account
   (email + phone verification).
2. Twilio starts you on a **free trial** with trial credit — enough to send
   a limited number of test messages to *verified* numbers only. To send
   real production SMS to arbitrary numbers, you'll need to **upgrade to a
   paid account** (Console → billing → "Upgrade"), which requires a credit
   card.
3. In the [Twilio Console](https://console.twilio.com/), the **Account
   SID** and **Auth Token** are shown directly on the dashboard home page —
   no separate generation step. Treat the Auth Token like a password: it
   authenticates every API call Twilio will accept from you.
4. **US A2P 10DLC registration:** sending application-to-person SMS from a
   US local number requires registering a "brand" and "campaign" with
   Twilio's compliance system before high-volume sending is allowed (a
   one-time, mostly-form-filling process in the Console under
   **Messaging → Regulatory Compliance**). Low-volume/testing traffic
   generally works without it, but do this before relying on SMS for real
   customer-facing notifications at any scale.
5. No phone number needs to be purchased by hand —
   `scripts/provision_twilio_number.py` searches and purchases one via the
   API once the account (and, for production use, 10DLC registration)
   exists.

### Cost

Twilio's US SMS pricing (verify current numbers at
[twilio.com/en-us/sms/pricing/us](https://www.twilio.com/en-us/sms/pricing/us)
before signing up):

- **Phone number rental:** a local (long code) number is about
  **$1.15/month**; toll-free is about **$2.15/month**.
- **Per-message:** about **$0.0083/segment** for outbound US SMS
  (inbound is billed too, at a similar rate), plus a small carrier
  pass-through surcharge (commonly a few tenths of a cent, and often an
  additional ~$1.50–$10/month in A2P 10DLC campaign fees once registered).
- For light usage (a few hundred messages/month), all-in cost is typically
  in the **$5–$15/month** range. **Verify current pricing on the link above
  before signing up** — Twilio's page is the source of truth.

### Generate the credential

The **Account SID** and **Auth Token** are visible on the Twilio Console
dashboard immediately after signup — nothing to "generate," just copy them.
The **phone number** (`TWILIO_FROM_NUMBER`) is what the provisioning script
purchases.

### Run the provisioning script

```bash
export TWILIO_ACCOUNT_SID=ACxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
export TWILIO_AUTH_TOKEN=<your auth token>

# Dry run first (default) — shows available numbers + estimated cost,
# purchases nothing:
python scripts/provision_twilio_number.py --area-code 617

# Only after reviewing the dry-run output, actually purchase a number:
python scripts/provision_twilio_number.py --area-code 617 --confirm
```

This spends real money on Cory's Twilio account the moment `--confirm` is
passed — the script defaults to a dry run specifically so nothing is
purchased by accident.

### Env vars to fill in afterward

```
TWILIO_ACCOUNT_SID=<from the Twilio Console dashboard>
TWILIO_AUTH_TOKEN=<from the Twilio Console dashboard>
TWILIO_FROM_NUMBER=<printed by the script after --confirm, e.g. +16175551234>
```

These map directly to `app/core/config.py`'s `twilio_account_sid` /
`twilio_auth_token` / `twilio_from_number` settings — setting all three
switches `app/services/sms.py` from console-fallback to real delivery.

## 3. Cloudflare (CDN + WAF)

**Why HarborIQ needs it:** puts a CDN and Web Application Firewall in front
of the reverse proxy documented in `docs/DEPLOYMENT.md`, caching static
frontend assets at the edge and adding a managed rule set against common
attack patterns (SQLi/XSS) in front of the API.

### Sign up (manual, in a browser)

1. Go to **<https://dash.cloudflare.com/sign-up>** and create an account
   (email + password, email verification).
2. Add the domain HarborIQ will run on ("Add a Site") — Cloudflare scans
   existing DNS records and asks you to update your registrar's nameservers
   to Cloudflare's. This nameserver change is the one step that has to
   happen at the domain registrar, not in Cloudflare itself, and can take
   anywhere from minutes to ~24 hours to propagate.
3. The **Free plan** is enough to complete every step in this guide (CDN,
   Managed Ruleset WAF, Cache Rules, Full-strict SSL/TLS are all available
   on Free) — no payment method is required unless upgrading to Pro/Business
   later for more custom WAF rules or advanced bot management.
4. Generate an **API Token** (not the legacy Global API Key — tokens are
   scoped, keys are all-or-nothing): **My Profile → API Tokens → Create
   Token**. Use the "Edit zone DNS" template as a starting point, or a
   custom token with these permissions scoped to the one zone:
   - Zone → SSL and Certificates → Edit
   - Zone → WAF → Edit
   - Zone → Cache Rules → Edit
   - Zone → Zone → Read
5. Find the **Zone ID**: Cloudflare dashboard → select the domain →
   right-hand sidebar on the Overview page, under "API" — it's a 32-char
   hex string.

### Cost

Cloudflare's **Free plan** includes the CDN (unlimited bandwidth, no
per-GB charges), Universal SSL, basic DDoS protection, and the WAF Managed
Ruleset used in this guide, all at **$0/month** — see
[Cloudflare's pricing page](https://www.cloudflare.com/plans/). Custom WAF
rules are capped at 5 on Free (rising to 20 on Pro at roughly $20–25/month,
and 100 on Business at roughly $200–250/month) — the single managed
ruleset + cache rule this guide provisions fits comfortably within Free.
**Verify current plan limits/pricing on the link above before signing up**
— Cloudflare revises plan tiers periodically.

### Generate the credential

The credential is the **API Token** generated in step 4 above, plus the
**Zone ID** from step 5 — both are dashboard actions, nothing to script.

### Run the provisioning script

> **This script is unvalidated against a live Cloudflare account** — no
> Cloudflare account existed in this project when it was written, so it has
> never been run against a real zone. Dry-run it and read every planned
> change carefully before passing `--apply`, and treat the first real run
> as a test to be verified by hand in the Cloudflare dashboard afterward,
> not a "fire and forget" step.

```bash
export CLOUDFLARE_API_TOKEN=<your API token>
export CLOUDFLARE_ZONE_ID=<your zone ID>

# Dry run first (default) — prints what WOULD change, changes nothing:
python scripts/provision_cloudflare.py --domain example.com

# Only after reviewing the dry-run output line by line:
python scripts/provision_cloudflare.py --domain example.com --apply
```

### Env vars to fill in afterward

```
CLOUDFLARE_API_TOKEN=<your API token>
CLOUDFLARE_ZONE_ID=<your zone ID>
```

These are **not** read by the FastAPI app itself — same
discoverability-only pattern as `BACKUP_S3_BUCKET` in `app/core/config.py`
— they exist in `.env.example` purely so the provisioning script above has
somewhere documented to read them from. See `docs/DEPLOYMENT.md`'s "CDN /
WAF (Cloudflare)" section for the full manual configuration reference this
script automates.

## Summary: what's scripted vs. what's manual

| Step                                              | AWS                        | Twilio                          | Cloudflare                          |
| -------------------------------------------------- | --------------------------- | --------------------------------- | -------------------------------------- |
| Create account, verify identity/payment            | **Manual** (browser)       | **Manual** (browser)             | **Manual** (browser)                  |
| Generate initial credential                        | Temporary admin key (manual, to run the script once) | **Manual** (Console dashboard)   | **Manual** (Console → API Tokens)     |
| Bucket / phone number / WAF & cache config          | `provision_aws_backup.py` | `provision_twilio_number.py`    | `provision_cloudflare.py`            |
| Final least-privilege credential used by HarborIQ  | Script-generated IAM user key | Console-provided SID/token (number is script-purchased) | Manually-generated scoped API token |

No script in this repo can create an AWS, Twilio, or Cloudflare account —
that always requires Cory's own identity and payment method in a browser.
